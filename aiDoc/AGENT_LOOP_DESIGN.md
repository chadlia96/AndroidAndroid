# Agent Loop 设计文档

本文只记录 androidAndroid 当前已经实现或讨论确认的 Agent Loop 设计。尚未确认的内容统一标记为 `待定`。

## 1. 当前阶段目标

当前阶段用于验证 Android 无障碍场景下的最小自动执行闭环:

- 接收用户任务目标。
- 采集当前应用、界面节点和 Toast 信息。
- 构建 Prompt 并请求模型决策。
- 解析并执行无障碍动作。
- 记录动作结果,等待界面稳定后继续下一轮。
- 通过悬浮窗和日志反馈运行状态。

当前实现属于实验性链路,不视为具备完整权限控制、结果校验或生产环境可靠性。

## 2. 输入与入口

聊天界面的 Agent 模式将用户文本交给 `NERV.submitUserInput()`,再由无障碍服务的协程调用 `AgentLoop.send()`。

普通文本对话和图片识别不进入 Agent Loop,仍由聊天模块直接调用对应模型能力。

当前没有额外的 `UserInput` 数据层。Agent Loop 直接接收字符串,首次输入作为 session 的 `goal`,后续输入写入 `metadata["last_user_input"]`。

## 3. AgentSession

当前只支持单个内存 session。非终态 session 会被继续使用;已经成功、失败或取消后,下一次输入会创建新 session。

`AgentSession` 当前保存:

- 固定的 `sessionId = "AGENT_LOOP"`。
- 用户目标 `goal`。
- `INIT`、`RUNNING`、`SUCCEEDED`、`FAILED`、`CANCELLED` 状态。
- 模型原始响应 `messages`。
- 动作执行结果 `actionExecutionResults`。
- 当前轮次、最大轮次和临时 `metadata`。
- 开始、更新和结束时间。

默认最大轮次为 30。Session 仅存在于当前进程内,暂不支持持久化、恢复或并行运行。

## 4. 当前主流程

```text
接收用户目标
  -> 创建或复用非终态 AgentSession
  -> 显示任务状态悬浮窗
  -> 首轮选择并启动目标应用
  -> 等待界面稳定
  -> 采集界面节点、当前应用和 Toast
  -> 构建 Prompt
  -> 请求模型并解析 AgentDecision
  -> 模型声明成功时结束 session
  -> 否则取本轮第一个动作执行
  -> 记录 ActionExecutionResult
  -> 等待界面稳定后进入下一轮
  -> 达到轮次或失败限制时结束 session
```

首轮固定执行 `launch_app`,由模型从已安装应用列表中选择目标应用。后续每轮最多执行一个模型动作,用于降低连续错误操作的风险。

动作执行后,界面连续 2 秒没有变化即视为稳定;单轮最多等待 15 秒。

## 5. 模型响应与动作协议

模型响应解析为 `AgentDecision`:

- `status`:当前任务状态。
- `agentActions`:候选动作列表。
- `reason`:模型给出的原因。
- `rawResponse`:保留的原始响应。

当前支持的 `AgentAction`:

- `click`:按当前界面节点编号点击。
- `input`:向指定节点输入文本。
- `swipe`:从起点坐标滑动到终点坐标。
- `launch_app`:选择并启动应用。
- `back`:返回上一页。
- `think_with_vision`:请求下一轮携带当前截图进行决策,不操作界面.

`click` 和 `input` 的 `target` 使用当前界面节点列表中的 1-based 编号。执行完成后统一生成 `ActionExecutionResult`,记录动作、目标、执行成功标记和说明。

## 6. 执行与反馈策略

除 `think_with_vision` 仅补充视觉输入外,上述动作当前均会真实调用 Android 无障碍能力执行,不再是只记录供人工操作的占位实现.

当前每轮手动推进的等待逻辑处于关闭状态,Agent 会自动进入下一轮。悬浮按钮和相关方法仍保留,但不代表当前启用了逐轮人工授权。

`TaskWatcher` 当前通过悬浮窗展示任务目标、模型请求状态、原始响应和成功状态。更详细的观察、解析、动作结果和失败原因仍记录在 Logcat。

## 7. 当前保护边界

- 每个 session 最多执行 30 轮。
- 每轮最多执行一个模型动作。
- 连续解析失败或空动作达到限制后终止 session。
- 无法读取当前界面时终止 session。
- 动作结果单独记录,不写回动作对象。

无障碍 API 返回成功只代表动作请求已被接受,不等价于任务目标已经完成。当前任务成功主要依赖模型在下一轮返回 `status = "success"`。

## 8. 按需视觉决策

- 默认使用节点摘要进行纯文本决策. 只有完成目标所必需的信息需要通过图像判断时,模型才请求 `think_with_vision`.
- 该请求只安排下一轮视觉输入,不操作界面,也不等待操作后的界面稳定.
- 下一轮重新采集节点摘要并截图,携带目标,历史,当前应用和 Toast,使用主模型和正常 `AgentDecision` 协议直接决策.
- 已处理视觉请求后,Prompt 和解析器均禁止再次输出 `think_with_vision`. 即使截图失败或响应解析失败,也保持禁止,直至执行一个普通动作后才恢复允许.
- 截图失败记录文字失败原因,随后使用现有文字信息决策,不得臆测图片内容.
- 图片仅作为当次请求的局部数据,不写入 Session 或后续历史. 视觉决策的简要 `reason` 作为文字结论进入历史.
- 节点列表为空时允许模型请求视觉补充,不因空节点直接结束. 无法获取无障碍根节点时仍终止 Session.
- 图片计费和模型兼容性需要通过实际服务调用验证,不预设节省比例.

## 9. 待定

- 暂停、继续、取消和用户补充输入的具体协议。
- 高风险动作分类、执行前确认和权限策略。
- 动作后页面变化与任务结果的独立校验机制。
- Session 持久化、流程记录和回放格式。
- 失败、取消和最终结果在聊天界面的统一回显格式。
